# Система учёта заказов интернет-магазина

Учебный проект по ПМ.03 «Ревьюирование программных модулей» для
специальности **09.02.07 «Информационные системы и программирование»**.

Проект представляет собой настольное приложение для учёта заказов
интернет-магазина. Реализован на **C#**, **Windows Forms** и **SQLite**.
В репозитории находятся две самостоятельные версии программы: базовая
версия 1.0 и расширенная версия **OrderFlow PRO 2.0**.

> **Рекомендуемая версия для демонстрации --- Version 2 Pro.** Она
> включает регистрацию и авторизацию пользователей, боковую навигацию,
> аналитику, настройки интерфейса, фильтрацию, экспорт и тест
> производительности.

## Возможности проекта

### Version 1.0 --- Basic

Первая версия предназначена для базового учёта заказов.

-   Просмотр заказов в таблице.
-   Добавление нового заказа.
-   Редактирование выбранного заказа.
-   Удаление заказа.
-   Поиск по номеру заказа, имени клиента и названию товара.
-   Хранение данных в SQLite.
-   Расчёт суммы заказа по формуле `Количество × Цена`.
-   Отображение общего количества заказов и общей суммы.

### Version 2.0 --- OrderFlow PRO

Вторая версия является расширенной и содержит дополнительные
возможности.

**Учёт заказов** - Просмотр заказов в таблице. - Добавление,
редактирование и удаление заказов. - Хранение имени клиента, электронной
почты, товара, категории, количества, цены, статуса и даты. -
Автоматический расчёт итоговой суммы заказа. - Поиск по номеру заказа,
клиенту, e-mail и товару. - Фильтрация по статусу и категории. -
Обновление списка заказов.

**Учётные записи** - Регистрация нового пользователя. - Вход по логину
или адресу электронной почты. - Выход из текущей учётной записи. -
Проверка уникальности логина и e-mail. - Проверка минимальной длины
пароля --- 8 символов. - Хранение паролей не в открытом виде, а в виде
хеша PBKDF2-SHA256 с индивидуальной случайной солью.

**Интерфейс и дополнительные разделы** - Боковая панель навигации. -
Раздел «Заказы». - Раздел «Аналитика» со сводными показателями. - Раздел
«Настройки» с информацией о профиле и переключателем тёмного фона
рабочей области. - Экспорт списка заказов в CSV. - Встроенный тест
производительности.

1.  Windows 10 или Windows 11.
2.  Microsoft Visual Studio 2026.
3.  Рабочая нагрузка Visual Studio **«Разработка классических приложений

4.  .NET 10 SDK.

## Запуск версии 1.0

1.  Склонировать репозиторий или скачать его архив с GitHub.
2.  Открыть папку `Version_1_Basic`.
3.  Запустить файл решения `OrderAccounting_v1.sln`.
4.  Дождаться загрузки проекта и восстановления NuGet-пакетов.
5.  При необходимости выбрать проект `OrderAccounting_v1` в качестве
    запускаемого.
6.  Нажать **F5** для запуска с отладчиком или **Ctrl + F5** для запуска

При первом запуске приложение автоматически создаёт локальную базу
данных SQLite.

Путь к базе данных:

``` text
%LocalAppData%\OrderAccountingV1\orders_v1.db
```

## Запуск версии 2.0 Pro

1.  Склонировать репозиторий или скачать его архив с GitHub.
2.  Открыть папку `Version_2_Pro`.
3.  Запустить файл решения `OrderAccounting_v2.sln`.
4.  Дождаться загрузки проекта и восстановления NuGet-пакетов.
5.  Убедиться, что запускаемым проектом выбран `OrderAccounting_v2`.
6.  Нажать **F5** для запуска с отладчиком или **Ctrl + F5** для запуска
    без отладки.

При первом запуске откроется окно авторизации.

### Первая регистрация

1.  Выбрать ссылку **«Нет аккаунта? Зарегистрироваться»**.
2.  Указать имя пользователя.
3.  Ввести адрес электронной почты.
4.  Придумать пароль длиной не менее 8 символов.
5.  Повторить пароль в поле подтверждения.
6.  Завершить регистрацию.
7.  Вернуться к форме входа и авторизоваться с созданными данными.

Требования к регистрации: - логин --- не менее 3 символов; - e-mail
должен содержать `@` и точку; - пароль --- не менее 8 символов; - логин
и e-mail должны быть уникальными.

Для учебной демонстрации рекомендуется использовать тестовые данные, а
не реальные пароли.

Путь к базе данных версии 2.0:

``` text
%LocalAppData%\OrderAccountingV2\orders_v2.db
```

## Работа с OrderFlow PRO 2.0

После успешной авторизации открывается главное окно программы с боковой
панелью навигации.

### Раздел «Заказы»

В разделе отображается таблица заказов. Для создания записи используется
кнопка добавления заказа. Для изменения или удаления необходимо выбрать
соответствующую строку таблицы.

В карточке заказа предусмотрены поля:

-   клиент;
-   e-mail;
-   товар;
-   категория;
-   количество;
-   цена;
-   статус;
-   дата создания.

Имя клиента и название товара обязательны. Если e-mail указан, он должен
содержать символ `@`. Количество должно быть положительным, цена не
может быть отрицательной.

Итоговая сумма вычисляется автоматически:

``` text
Итоговая сумма = Количество × Цена
```

Для быстрого поиска можно ввести часть номера заказа, имени клиента,
e-mail или названия товара. Дополнительно доступны фильтры по статусу и
категории. Чтобы вернуться к полному списку, очистите строку поиска и
выберите значения «Все статусы» и «Все категории».

### Раздел «Аналитика»

Раздел отображает сводную информацию:

-   общее количество заказов;
-   общую сумму заказов;
-   количество новых заказов;
-   количество доставленных заказов;
-   распределение заказов по статусам: «Новый», «В обработке»,
    «Доставлен» и отменённые.

Показатели формируются на основании записей в базе SQLite.

### Раздел «Настройки»

В настройках отображаются имя текущего пользователя, название приложения
и сведения о локальном хранилище SQLite.

Доступен переключатель **«Тёмный фон рабочей области»**. Изменение
применяется к рабочей области приложения в текущем сеансе. Для выхода из
учётной записи используется соответствующая команда на боковой панели.

### Экспорт в CSV

1.  Открыть раздел «Заказы».
2.  При необходимости задать поиск и фильтры.
3.  Нажать кнопку **«Экспорт CSV»**.
4.  Выбрать папку и имя файла.
5.  Подтвердить сохранение.

В CSV-файл включаются отображаемые по заданным условиям записи и поля
заказа: номер, клиент, e-mail, товар, категория, количество, цена,
статус, дата и итоговая сумма.

### Демонстрационные данные

При первом создании базы данных версии 2.0 приложение заполняет таблицу
заказов демонстрационными записями, если она ещё пуста. Это позволяет
сразу проверить таблицу, фильтры и аналитику. Если в базе уже есть
заказы, повторное заполнение не выполняется.

## База данных

Для хранения данных используется SQLite. Отдельный сервер баз данных
устанавливать не требуется: база хранится в локальном файле на
компьютере пользователя.

### База версии 1.0

``` text
%LocalAppData%\OrderAccountingV1\orders_v1.db
```

Основная таблица `Orders` содержит сведения о заказах: идентификатор,
клиента, товар, количество, цену, статус, дату создания.

### База версии 2.0

``` text
%LocalAppData%\OrderAccountingV2\orders_v2.db
```

В версии 2.0 используются таблицы:

-   `Orders` --- сведения о заказах;
-   `Users` --- учётные записи пользователей, соль и хеш пароля.

Для работы с базой используется NuGet-пакет `Microsoft.Data.Sqlite`.
SQL-запросы выполняются через параметризованные команды.

**Важно:** базы двух версий хранятся в разных каталогах и не являются
общей базой данных. Удаление файла базы приведёт к потере сохранённых в
нём данных. Перед ручным изменением или переносом базы рекомендуется
закрыть приложение и сделать резервную копию файла.

## Вычислительный эксперимент

В версии 2.0 предусмотрена команда **«Тест скорости»**. Она выполняет
два измерения:

1.  Время чтения заказов из базы SQLite.
2.  Время поиска по тестовой коллекции из 50 000 объектов в оперативной
    памяти.

По завершении теста приложение показывает: - количество прочитанных из
SQLite заказов; - время чтения в миллисекундах; - время поиска в
миллисекундах; - количество найденных объектов.

Результаты зависят от характеристик компьютера, состояния системы и
объёма базы данных. Поэтому при оформлении отчёта следует использовать
значения, фактически полученные при запуске эксперимента, а не заранее
заданные или предполагаемые показатели.

Для повторного сравнения рекомендуется выполнять тест несколько раз при
одинаковых условиях и записывать результаты каждого запуска.

## Сборка проекта

Сборку можно выполнить через Visual Studio или командную строку .NET
SDK.

### Через Visual Studio

1.  Открыть нужный файл `.sln`.
2.  Выбрать конфигурацию `Debug` или `Release`.
3.  В меню **Сборка** выбрать **Собрать решение**.
4.  Проверить результат в окне **Список ошибок**.

### Через командную строку

Для версии 1.0:

``` powershell
dotnet restore .\Version_1_Basic\OrderAccounting_v1.sln
dotnet build .\Version_1_Basic\OrderAccounting_v1.sln -c Release
```

Для версии 2.0:

``` powershell
dotnet restore .\Version_2_Pro\OrderAccounting_v2.sln
dotnet build .\Version_2_Pro\OrderAccounting_v2.sln -c Release
```

Если сборка завершается ошибкой, проверьте установленную версию .NET SDK
командой:

``` powershell
dotnet --list-sdks
```

В списке должна присутствовать версия SDK 10.0.x.

## Отладка

Для отладки рекомендуется использовать Microsoft Visual Studio 2026.

1.  Открыть соответствующее решение `.sln`.
2.  Установить конфигурацию `Debug`.
3.  Открыть нужный исходный файл `.cs`.
4.  Установить точку останова щелчком слева от номера строки.
5.  Запустить приложение клавишей **F5**.
6.  Выполнить действие, которое требуется проверить.
7.  При остановке на точке останова изучить значения переменных и стек
    вызовов.
8.  Для продолжения выполнения использовать **F5**, для пошагового
    выполнения --- **F10** или **F11**.

Для анализа ошибок также можно использовать окна **«Список ошибок»**,
**«Вывод»** и **«Локальные»**.

## Работа с Git и GitHub

Чтобы получить локальную копию репозитория:

``` bash

```
